## 2. Google Play SMS & Call Log Permissions Declaration (P0 Policy Gate)

Google Play strictly restricts `RECEIVE_SMS` and `READ_SMS` to apps where SMS is an essential core functionality. Because Hospital CRM operates as an in-clinic merchant point-of-sale terminal to reconcile front-desk UPI payments (e.g., GPay, PhonePe, Paytm, BHIM), the following declaration must be submitted in the Play Console **Permissions Declaration Form**:

### Declaration Answers:

1. **Declared Permission:**
   - `RECEIVE_SMS`
2. **Core Feature Category:**
   - Select: **Financial transaction SMS confirmation / Point-of-Sale (POS) SMS validation**
3. **Core Functionality Justification:**
   > "SamStack Hospital CRM is an operational clinic management and front-desk billing system. In Indian outpatient clinics, patients frequently pay consultation and pharmacy bills via dynamic or static UPI QR codes. Bank confirmation SMS alerts (containing amount, timestamp, and unique transaction reference / UTR) are sent to the clinic front-desk phone. 
   > 
   > The app uses `RECEIVE_SMS` exclusively to detect incoming bank credit notifications locally on the clinic front desk terminal, extract the UTR reference number and payment amount via regular expressions, and match them in real time with the active invoice awaiting payment. 
   > 
   > This prevents patients from waiting in queues while receptionists manually cross-check bank accounts. At no point is personal SMS data stored or transmitted: non-transaction messages and debit alerts are instantly discarded on-device, only the 12-digit UTR reference and amount are queued, and the transaction is cryptographically signed using Android Keystore AES-GCM before server reconciliation."
4. **Why alternative APIs (e.g. SMS Retriever API / SMS User Consent API) cannot be used:**
   > "The SMS Retriever API requires an 11-character hash appended to the SMS text by the sender. Bank credit confirmation SMS messages are generated by external banking aggregators and automated core banking systems (e.g., HDFC, ICICI, SBI, NPCI UPI) where adding custom application hashes is impossible. The SMS User Consent API prompts for manual user interaction on each incoming SMS, which interrupts active clinical workflows and prevents automated reconciliation during busy patient queues."
5. **Video Demonstration Link:**
   - Upload a 60–90 second YouTube (Unlisted) video demonstrating:
     1. Clinic Admin enabling the Payment Bridge in Settings.
     2. Pairing the device with the clinic's tenant key.
     3. Opening Billing / POS.
     4. Receiving a bank UPI credit SMS notification.
     5. The app matching the amount and UTR to mark the invoice as Paid in real time.

## 3. Google Play Data Safety Form Answers

| Category | Item | Collected? | Shared with 3rd Parties? | Purpose | Ephemeral / Retained? |
|---|---|---|---|---|---|
| **Personal Info** | Name, Phone Number | Yes | No | Patient registration & appointment booking | Retained within tenant DB; 24h TTL in offline local cache |
| **Financial Info** | Payment records, UTR | Yes | No | Invoice generation & tax compliance | Retained for clinic tax records |
| **Health Info** | Clinical notes, vitals, prescriptions | Yes | No | Healthcare documentation (EHR/OPD) | Retained (append-only audit trail) |
| **Device Identifiers** | `X-Device-Id` (UUID) | Yes | No | Cryptographic request signing & device pairing (Keystore HMAC) | Stored encrypted in Android Keystore |
| **SMS Data** | Bank UTR / amount text only | Yes (local parse) | No | Payment reconciliation | Local parsing only; full SMS text is never uploaded |

### Security Practices:
- **Data Encrypted in Transit:** Yes (TLS 1.3 / HTTPS strictly enforced in release builds).
- **Data Encrypted at Rest:** Yes (Android Keystore AES-256-GCM for secrets; encrypted SQLite / PostgreSQL).
- **Data Deletion Mechanism:** Yes (Clinics and patients can submit data purge requests to `privacy@samstack.ai`).
- **Target Audience:** Not directed at children under 13.

## 4. Production Privacy Policy Template

```markdown
# Privacy Policy — SamStack Hospital CRM
Last Updated: October 21, 2026

SamStack AI ("we", "our", or "us") provides the SamStack Hospital CRM software suite, including web applications and mobile applications (the "Service"). This Privacy Policy describes how we handle sensitive personal information, personal health information (PHI), and device data.

### 1. Information We Collect
1. Patient Data: Names, age, gender, contact details, vital signs, clinical consultation notes, and prescription history entered by authorized healthcare providers.
2. Financial & Billing Information: Invoice items, GST breakdown, payment method, and transaction reference numbers (UTR).
3. Device & Authentication Data: Unique device identifiers used solely to bind the hardware terminal to a specific clinic tenant using hardware-backed cryptographic keys (Android Keystore).

### 2. SMS Permission & Usage (`RECEIVE_SMS`)
Our mobile application requests access to incoming SMS messages for one specific purpose:
- To automatically detect incoming bank and UPI credit confirmation notifications on the clinic front-desk device.
- The app parses only the transaction amount and the 12-digit UTR reference code.
- Personal SMS, non-transaction messages, and debit alerts are immediately discarded on the device.
- Full SMS message bodies are NEVER transmitted to our servers or shared with any third party.

### 3. Data Protection and Encryption
- All data in transit between the mobile application and our backend is encrypted using industry-standard TLS (Transport Layer Security).
- Paired device authentication secrets are stored in hardware-backed storage (Android Keystore with AES-GCM encryption).
- All patient records and clinical notes adhere to strict tenant isolation and append-only audit logging.

### 4. Data Retention and Deletion
Healthcare records are retained in compliance with applicable statutory healthcare retention laws. Patients and clinics may request data portability or account deletion by contacting support@samstack.ai.

### 5. Contact
SamStack AI Technologies
Email: privacy@samstack.ai | Website: https://samstack.ai
```
